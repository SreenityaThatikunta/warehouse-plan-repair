# Design Decisions

| # | Decision | Rationale |
|---|---|---|
| D1 | Initial MAPF uses **prioritized planning with Space-Time A\*** and a reservation table. The longest task chain goes first, with random restarts on failure | Recommended by the assignment. It is fast and scales to 50+ agents. Reservations can be edited per agent, which is what local repair needs. |
| D2 | Multi-goal ST-A* with state `(x, y, goal_idx, t)`. The heuristic is the exact static distance through the remaining goals | Plans an agent's whole pickup→delivery→…→home chain in one search, with no gluing of separate segments. |
| D3 | Repair is **tiered**: solo replan → negotiate with the smallest set of neighbours that block the agent, growing the set → the same with radius 2R → hold and retry | Tries the options that change the fewest agents first, which directly serves the goal of "minimise the number of agents altered". |
| D4 | The global planner is never called during local repair. Full replan exists only as a **baseline** | The assignment says repair must not start from scratch. The baseline measures what staying local costs. |
| D5 | "Agents altered" means the future path after repair differs from the path just before the disruption. Cascades count toward the triggering disruption. We also report `direct` (robots whose plan the event itself invalidated) and `collateral` (= altered − direct) | Gives each disruption a clear count that can be measured, and separates unavoidable changes from those the repair caused. |
| D6 | Emergency agents get top priority in negotiation (they plan first) and negotiate for any detour (δ = 0). Other robots can't make an emergency robot move | Emergency tasks are high priority by definition. |
| D7 | Permanent breakdown: the broken robot's unfinished tasks are auctioned to robots within radius R, doubling R if nobody is in range. The lowest marginal cost wins. A carried item is handed off at a reachable free cell next to the broken robot | Only the winning robot's plan changes. The auction is a standard decentralised allocation method. |
| D8 | **Tier 0 (a separate wait-only check) was dropped.** Solo ST-A* already considers waiting and returns the best wait-or-detour plan | It adds nothing to cost or to the number of altered agents. |
| D9 | Accepting a negotiation: a coalition S is accepted only if `extra delay of S and the agent + λ·|S| < solo detour delay`. Defaults: λ = 3, δ = 4, R = 6, at most 3 coalition members, and only robots that block the agent's ideal path are candidates. The smallest size that works wins | Balances fewer altered agents against total time. λ sets the price of changing one more robot's plan. |
| D10 | Robots **return to their dock** after their last task. Docks are **dead-end bays** (no sideways moves between docks) | Robots must park somewhere. Parking at stations or in aisles blocks others, and when docks formed a through-row, robots drove through other robots' docks, which forced long waits before those robots could park. |
| D11 | Main metric SoC = Σ over robots of the time of the last delivery. Makespan = the latest delivery. Travel back to the dock is excluded, but reported separately as `soc_total` | "Time to accomplish their tasks". |
| D12 | ST-A* uses a lower bound on the earliest time the robot can park at its final goal (after every other reservation of that cell), plus a fast reachability check for impossible cases | Without these, searches flooded huge plateaus of states when the goal cell was still in use by others, which made full replanning fail or take seconds. |
| D13 | Robots learn a blockage's duration when it occurs, for example from a maintenance estimate. Future disruptions are never known in advance | Realistic, and repair needs an end time for temporary obstacles. |
| D14 | Hold (Tier 4) = the robot stays on its cell with a "parked" reservation and retries every step. On retry, **negotiation is allowed under every strategy** | Two robots on hold can block each other forever (seen in 1-wide aisles). Only a joint replan breaks that deadlock. |
| D15 | Full-replan baseline: all live robots are re-planned with prioritized ST-A* from the current state (emergency and broken robots first), with up to 5 random restarts. If that fails, it falls back to local repair | Gives an honest comparison: the best the global planner can do at that moment, and how many robots it changes. |
| D16 | Blockages avoid docks, stations, occupied cells and cells that are still some robot's goal. Permanent ones also must not disconnect the map. Emergency cells are checked for reachability when the event fires | Keeps every task solvable, so failures come from repair rather than from impossible instances. |
| D17 | **Chained negotiation (v2).** A coalition member that cannot replan, or only with a delay above δ, may recruit up to 2 of its own blockers within its own radius R, at most 2 hops deep and 6 robots per tree. Its blockers are found from its *relaxed* path: its best path if the movable robots in its range made way. The whole tree is scored with the same rule `delay + λ·|altered|`, compared with going solo | Taken from a peer implementation, which used recursive negotiation but accepted any chain that worked. Scoring the whole tree keeps "change as few robots as possible". The relaxed path matters: a parked robot's robot-free ideal path is "stay put", which would never reveal the robot blocking its escape (see the pocket test). |
| D18 | **Tier 3b: local group replan (v2), recorded as tier 6.** Prioritized ST-A* for the stuck robot plus the movable robots within 2R whose plans cross its ideal corridor (at most 8). It is accepted under the same score rule. It runs only for **urgent** robots: emergency robots, or robots with no solo path at all (`group_scope='urgent'`) | The peer fell back to *global* replanning, which our rules forbid; this is the local equivalent. With `group_scope='all'` at 50 robots (10 seeds), total time improved by 32 steps but robots altered per disruption rose by 0.62 (limit +0.3). Restricted to urgent robots it changes ≤ the v1 count and keeps most of the emergency gain. |
| D19 | **Emergency deadline (v2).** At the event, deadline = the robot's robot-free delivery time + 3 steps. Any plan that makes an emergency delivery miss its deadline costs `deadline_penalty` (10) in every repair comparison, and emergency robots may form coalitions of up to 4. `emergency_on_time` and `emergency_lateness` are reported for every strategy | The peer enforced a deadline but never measured it. Here the guarantee is measured, so it is not just assumed. A task stranded on a permanently broken robot counts as not on time. |
| D20 | **Expanding-ring hold (all strategies).** A robot on hold for 10 or more steps doubles its search radius every 10 steps (2R → 4R → …, capped at the map size), for negotiation and tier 3b | A two-robot deadlock 16 cells apart (beyond 2R = 12) was found with `--agents 40 --seed 1` under the CLI defaults: each held the cell the other needed, and both waited forever. v1 had this bug too, so the fix applies to every strategy and keeps the comparison fair. |
| D21 | Strategies: `local` = v2 (D17–D19), `local-flat` = v1 (flat coalitions, no tier 3b, no deadline term) + D20, `local-nochain` = v2 without chains (robots sweep only), `solo`, `full` | Measures each v2 addition against the v1 method on the same seeds. |
| D22 | No PDF report generator | Dropped at the user's request (2026-10-03). |
| D23 | Chained negotiation stays **on** by default, even though the sweep shows no clear gain | `local-nochain` is within noise of `local` (at 50 robots: SoC 6963 vs 6958, altered 5.72 vs 5.88) at about half the repair time. Chains are what make the pocket case solvable, and they were explicitly requested. Turning them off is `chain_depth=1`. Revisit if repair time matters. |
| D24 | Known limitation: `solo` can gridlock the whole fleet (50 robots, permanent breakdown, seed 5) | Without negotiation, only the hold-retry deadlock breaker can move robots, and 49 mutually-holding robots exceed what it can untangle. It is an ablation, and it happens in v1 too. `local` and `local-flat` solve the same instance, which shows that negotiation is needed. |
| D25 | **Failure study:** a `safe` switch for the D16 filters, stall detection (150 steps with no movement or goal reached) and an unreachable/deadlock label for each stuck robot | The assignment's report must show settings where agents fail. With the filters on, failures are almost absent, which overstates robustness. Stall detection keeps runs that cannot succeed from spinning to `max_steps`, which would cost minutes per run in retries. |
| D26 | Report in **LaTeX** (`report/report.tex`, `pdflatex`), **9 pages, plain but formal language**, with no abstract, date, code blocks or repo link | User's choice: LaTeX, then concise (5 pages, later 6, then 7 to fit the scaling results), with just a link to the repo. The failure section, first kept in `failures.tex`, was merged into the main file when the report was cut down. |
| D27 | The **hold cascade** found in the stress study (F3) is reported as a weakness, not fixed now | One temporary breakdown on a crowded small map can make all 40 robots hold, each treating the others as walls, and coalitions (≤4) and Tier 3b (≤8) are too small to untangle it, while `full` solves it. Candidate fixes are an escalation to a regional replan once a cascade exceeds k robots, and letting robots with unreachable goals release the task and move aside (F2). Both change the method and would need a rerun, so they are left as future work unless requested. |
